# ESP32 + HUB75: память и частота обновления

## Память DMA (библиотека ESP32-HUB75-MatrixPanel-DMA 3.x)
На каждую пару строк и каждый бит цвета выделяется `ширина_цепочки × 2 байта`
(на исходном ESP32 параллельный вывод идёт 16-битными словами).

```
память = (высота / 2) × ширина_цепочки × 2 байта × бит_цвета × (2, если двойной буфер)
```

Наш случай: высота 64, цепочка 2 × 128 = 256.

| Бит | Память |
|---|---|
| 4 | 64 КБ |
| 5 | 80 КБ |
| **6** | **96 КБ** |
| 7 | 112 КБ |
| 8 | 128 КБ |

Исходному ESP32 под DMA доступно примерно 200 КБ внутренней RAM (PSRAM для DMA на нём
не используется). Wi-Fi + lwIP + веб-сервер забирают ещё ~50–70 КБ кучи. Отсюда выбор 6 бит.

Проверка на железе: `panel_test` печатает `DMA used / DMA free`, основная прошивка — `status`.

## Частота обновления
Время вывода одного кадра ≈ (число строк развёртки) × (сумма весов битовых плоскостей) ×
(ширина + накладные) / частота тактирования. Библиотека автоматически подбирает
`lsbMsbTransitionBit`: младшие биты выводятся с неточным весом, если иначе частота упадёт
ниже `min_refresh_rate` (у нас 60 Гц). Фактическое значение — `calculated_refresh_rate`.

Что можно крутить:
- `i2sspeed` (8 → 16/20 МГц) — выше частота, но нужны короткий шлейф и хорошая земля;
- `kColorDepthBits` — меньше бит, выше частота;
- `min_refresh_rate` — ниже требование, точнее цвета.

## Яркость
`setBrightness8()` меняет длительность OE, а не данные — биты цвета не теряются. Поэтому
лимитер тока в `Display` работает через неё.

## Если памяти не хватит
1. 5 бит.
2. Выключить Bluetooth (в Arduino он и так не инициализирован).
3. `Frame` в RGB565 (32 КБ вместо 48 КБ) — ценой точности цвета сцен.
4. ESP32-S3 с PSRAM (ограничение частоты вывода ~13 МГц).
