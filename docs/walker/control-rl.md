# Ходок — управление и RL

## Уровни управления
| Уровень | Где | Частота | Что |
|---|---|---|---|
| Серво | в серво | ~1 кГц | ПИД по положению (встроенный) |
| Походка | **борт**, Pi Zero 2 W | 50 Гц | RL-политика: наблюдения → целевые углы |
| Поведение | ПК/телефон или борт | 1–10 Гц | куда идти, настроение, реакции на стук, сцены светильника |

Почему походка на борту: задержка Wi-Fi обычно 5–30 мс, но бывают провалы на 100+ мс, для
цикла баланса на 50 Гц это плохо. Небольшая сеть (MLP 3×256, ~150 тыс. умножений) на
Pi Zero 2 W — доли миллисекунды (Open Duck Mini так и работает). На прототипе можно
пробовать удалённый режим (четвероногий терпимее двуногого), но цель — борт (ADR 0007).

ESP32-S3 тоже потянул бы маленькую сеть (int8), но отладка на Pi проще: Python, ONNX,
логирование, Wi-Fi-телеметрия.

## Этапы
1. **B0 — модель.** Параметрическая MJCF: корпус (масса/инерция светильника + шасси),
   ноги-пятизвенники через ограничение `equality/connect` (замкнутая цепь), позиционные
   актуаторы с ограничением момента. Задачи: стоит ли, какие моменты в стойке/приседе/рыси,
   подбор L1/L2 и развала.
2. **B1 — стенд.** Одна нога, 2 серво. Идентификация серво: ступенчатые отклики, зависимость
   момента от ошибки положения/скорости, трение, люфт, задержка шины. По результатам —
   модель актуатора в симуляции.
3. **B2 — классика.** Обратная кинематика + генератор рыси без обучения: проверка железа,
   питания, частоты цикла.
4. **B3 — RL в симуляции.**
5. **B4 — перенос на железо.**

## Обучение
| | |
|---|---|
| Симулятор | **MuJoCo Playground** (MJX/JAX, тысячи сред на GPU); альтернатива — Isaac Lab |
| Где | ноутбук RTX 3080 Mobile 16 ГБ (основной), 3070 Ti 8 ГБ (запасной) |
| ОС | JAX с GPU — только Linux → **WSL2** на Windows ([wiki/dev-setup.md](../wiki/dev-setup.md)) |
| Алгоритм | PPO (есть в Playground/Brax) |
| Экспорт | ONNX → `onnxruntime` на Pi |

### Наблюдения (черновик)
- проекция вектора гравитации в осях корпуса, угловая скорость (IMU);
- положения и скорости суставов (из серво);
- предыдущее действие;
- команда: vx, (vy — стадия 2), угловая скорость по вертикали;
- фаза походки (sin/cos) — по желанию;
- контакт стоп — если будут датчики.

### Действия
Смещения целевых углов серво от стойки, 50 Гц, с ограничением скорости изменения.

### Награды (черновик)
- следование командной скорости (линейной и угловой);
- ровный корпус, высота корпуса;
- штрафы: скорость изменения действий, момент/мощность, скольжение стоп,
  удары стоп, приближение к пределам суставов;
- время в воздухе стоп (походка, а не шарканье);
- **«характер»**: следование референсной анимации (подход Disney BDX / Open Duck) — ключ
  к «естественности».

### Рандомизация (для переноса)
Масса и центр масс корпуса ±20%, трение 0,4–1,2, коэффициенты серво ±20%, момент по
напряжению аккумулятора, задержка 0–20 мс, шум IMU и энкодеров, **толчки** (они же — стук
по светильнику).

## Удалённая часть
- Pi публикует телеметрию (углы, токи, IMU, действия) по Wi-Fi → ПК пишет логи для анализа
  и дообучения.
- ПК отправляет команды верхнего уровня (скорость, поза, сцена светильника).
- Позже: камера/голос/LLM на ПК или телефоне.
